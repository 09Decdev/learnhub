# Chương 12 · Serverless Application Model (SAM)

Học xong chương này, bạn **viết, test và deploy một ứng dụng serverless** (Lambda + API Gateway + DynamoDB) chỉ bằng một file `template.yaml` và vài lệnh `sam`. Bạn cũng dựng được một app rút gọn link hoàn chỉnh, gần như miễn phí nếu nằm trong Free Tier.

Các lệnh bạn sẽ gõ nhiều nhất:

```bash
sam init                 # tạo project mẫu
sam build                # cài thư viện, đóng gói code vào .aws-sam/build
sam local invoke         # chạy thử 1 Lambda trên máy (cần Docker)
sam local start-api      # dựng API giả trên http://127.0.0.1:3000
sam deploy --guided      # deploy lần đầu, hỏi từng tham số và lưu vào samconfig.toml
sam logs --tail          # xem log CloudWatch
sam delete               # xoá stack
```

## Serverless, SAM và cấu trúc file template {001-003}

**Khái niệm cốt lõi**

**Serverless** không có nghĩa là không có server. Nó có nghĩa là **bạn không quản lý server**: không chọn EC2, không vá hệ điều hành, không lo scale. Bạn trả tiền theo **số lần gọi và thời gian chạy**; không ai dùng thì gần như 0 đồng.

Ba dịch vụ của chương:
- **AWS Lambda:** chạy một *hàm* code (Python, Node.js, Java…) khi có sự kiện (HTTP request, file lên S3, lịch cron…).
- **Amazon API Gateway:** cửa ngõ HTTP. Nhận request từ Internet rồi gọi Lambda.
- **Amazon DynamoDB:** database NoSQL dạng key-value, serverless, không cần dựng máy.

```
Trình duyệt ──HTTPS──▶ API Gateway (/dev/api/generate-short-url)
                           │ event JSON
                           ▼
                     Lambda (Python) ──boto3──▶ DynamoDB (UrlShortenTable)
                           │
                     CloudWatch Logs (/aws/lambda/<tên-hàm>)
```

**SAM là gì?** **AWS SAM (Serverless Application Model)** gồm hai phần:
1. **Cú pháp template:** một phần mở rộng của CloudFormation, viết gọn tài nguyên serverless. 10 dòng SAM có thể sinh ra Lambda + IAM role + API Gateway + permission, tương đương khoảng 80 dòng CloudFormation.
2. **SAM CLI:** công cụ dòng lệnh để build, chạy thử trên máy, deploy và xem log.

**Cấu trúc file `template.yaml`** (đối chiếu với `serverless-application-model/url-shorten-app/template.yaml`):

```yaml
AWSTemplateFormatVersion: '2010-09-09'
Transform: AWS::Serverless-2016-10-31     # ← dòng "thần kỳ": bảo CloudFormation dịch cú pháp SAM

Description: url-shorten-app

Globals:                # thiết lập dùng chung cho mọi Function / Api
  Function:
    Timeout: 10         # giây
    Tracing: Active     # bật AWS X-Ray
    LoggingConfig:
      LogFormat: JSON   # log dạng JSON, dễ lọc bằng CloudWatch Logs Insights

Parameters: {}          # (tuỳ chọn) tham số nhập lúc deploy, ví dụ Stage=dev/prod

Resources:              # BẮT BUỘC: tài nguyên cần tạo
  MyFunction:
    Type: AWS::Serverless::Function
    Properties: { CodeUri: hello_world/, Handler: app.lambda_handler, Runtime: python3.11 }

Outputs:                # giá trị in ra sau deploy (URL API, ARN…)
  ApiUrl:
    Value: !Sub "https://${MyApi}.execute-api.${AWS::Region}.amazonaws.com/dev/"
```

**Các loại tài nguyên SAM hay gặp:**

| SAM | Sinh ra (CloudFormation) |
|---|---|
| `AWS::Serverless::Function` | Lambda function + IAM role (nếu không chỉ định) + permission + event source |
| `AWS::Serverless::Api` | API Gateway **REST API** + stage + deployment |
| `AWS::Serverless::HttpApi` | API Gateway **HTTP API** (rẻ hơn, nhanh hơn) |
| `AWS::Serverless::SimpleTable` | DynamoDB table đơn giản (1 khoá chính) |
| `AWS::Serverless::LayerVersion` | Lambda Layer (thư viện dùng chung) |
| `AWS::Serverless::StateMachine` | Step Functions |

Bạn vẫn viết được mọi tài nguyên CloudFormation thường (`AWS::DynamoDB::Table`, `AWS::IAM::Role`…) trong cùng file, như lab đang làm.

**Đi sâu hơn: SAM so với các công cụ khác**

| Công cụ | Ngôn ngữ | Mạnh ở | Lưu ý |
|---|---|---|---|
| **SAM** | YAML (CloudFormation) | Serverless trên AWS, test local bằng `sam local`, canary Lambda dễ | Chỉ AWS; YAML dài khi app lớn |
| **AWS CDK** | TypeScript/Python/Java… | Viết hạ tầng bằng ngôn ngữ lập trình, có vòng lặp, kế thừa | Cuối cùng vẫn sinh ra CloudFormation; học lâu hơn |
| **Serverless Framework** | YAML + plugin | Nhiều plugin, từng rất phổ biến | Từ v4, tổ chức có doanh thu lớn phải trả license |
| **Terraform** | HCL | Đa cloud, một công cụ cho mọi hạ tầng (chương 05) | Không có sẵn "chạy Lambda local"; phải tự đóng gói zip |

Cách nhớ: dự án **chỉ có serverless trên AWS** thì SAM nhanh nhất. Hạ tầng **lẫn nhiều thứ** (VPC, EKS, RDS, nhiều cloud) thì Terraform. Thích **viết code** hơn YAML thì CDK.

**Lỗi hay gặp & cách sửa**

- Thiếu dòng `Transform:` → CloudFormation báo `Unrecognized resource types: [AWS::Serverless::Function]`.
- Thụt lề YAML sai → `sam validate` báo `Error: ... is not a valid SAM template`. Chạy `sam validate --lint` trước khi deploy (repo đã bật `lint = true` trong `samconfig.toml`).
- `Globals` đặt thuộc tính mà loại tài nguyên không hỗ trợ → lỗi khi transform. Không phải thuộc tính nào cũng đặt được trong `Globals`.

🟡 *Thực hành*: Sau khi deploy ở lab1, mở CloudFormation → stack → tab *Resources*. Đếm số tài nguyên thực tế được tạo, so với số tài nguyên bạn viết trong template. Những tài nguyên "thêm" là gì?

<details><summary>Gợi ý</summary>

</details>

🔴 *Thử thách*: Viết cùng một Lambda + API (1 route GET) bằng SAM và bằng Terraform (`aws_lambda_function`, `aws_apigatewayv2_api`, `archive_file`…). So số dòng và liệt kê những thứ bạn phải tự viết ở Terraform mà SAM làm hộ. Nhớ `sam delete` và `terraform destroy`.

**Câu hỏi tự kiểm tra**

<details><summary>1. Dòng <code>Transform: AWS::Serverless-2016-10-31</code> làm gì?</summary>

Nó bảo CloudFormation chạy *macro* SAM trước khi tạo tài nguyên: dịch `AWS::Serverless::Function`, `Api`… thành tài nguyên CloudFormation chuẩn (Lambda, IAM Role, API Gateway, Permission…). Bạn xem kết quả dịch được ở tab *Template → View processed template* của stack.
</details>

<details><summary>2. "Serverless thì không tốn tiền" đúng hay sai?</summary>

Sai. Bạn không trả tiền cho máy *đứng chờ*, nhưng vẫn trả theo số request, thời gian chạy, dung lượng lưu trữ, log và X-Ray. Free Tier rất rộng nên app học tập thường gần 0 USD. Tuy nhiên, một vòng lặp vô hạn (Lambda tự gọi chính nó) hoặc bị spam API có thể tạo hoá đơn lớn.
</details>

## Lab1 · Hello World với SAM: build và deploy {004-005}

**Khái niệm cốt lõi**

Lab theo file `serverless-application-model/Command.md`: cài công cụ, `sam init`, `sam build`, `sam deploy --guided`, rồi gọi API.

```bash
# Cài SAM CLI trên Fedora (x86_64)
curl -LO https://github.com/aws/aws-sam-cli/releases/latest/download/aws-sam-cli-linux-x86_64.zip
unzip aws-sam-cli-linux-x86_64.zip -d sam-installation
sudo ./sam-installation/install
sam --version

aws sts get-caller-identity          # chắc chắn AWS CLI đã đăng nhập
sam init --runtime python3.11        # chọn "Hello World Example"
cd sam-app
sam build
sam deploy --guided
```

**Bên trong `sam build` và `sam deploy`:**

```
sam build : đọc template → cài requirements.txt cho từng hàm → .aws-sam/build/<Hàm>/
            + sinh .aws-sam/build/template.yaml (CodeUri trỏ vào thư mục đã build)
sam deploy: nén code → upload lên S3 (bucket do SAM tự tạo: stack "aws-sam-cli-managed-default")
            → tạo CloudFormation changeset → (hỏi xác nhận) → thực thi changeset
```

**Hàm Lambda tối thiểu** (`hello_world/app.py`):

```python
import json

def lambda_handler(event, context):        # Handler: app.lambda_handler
    # event: dữ liệu request do API Gateway gửi (path, headers, body…)
    # context: thông tin lần chạy (request id, thời gian còn lại…)
    return {
        "statusCode": 200,                  # API Gateway (proxy) cần đúng format này
        "body": json.dumps({"message": "hello world"}),
    }
```

**Các câu hỏi của `sam deploy --guided`** và nên trả lời thế nào:

| Câu hỏi | Gợi ý |
|---|---|
| Stack Name | `sam-app` (tên stack CloudFormation) |
| AWS Region | `ap-southeast-1` |
| Confirm changes before deploy | `Y`: xem trước thay đổi, giống `terraform plan` |
| Allow SAM CLI IAM role creation | `Y`: SAM cần tạo role cho Lambda |
| Disable rollback | `N` cho người mới: deploy lỗi thì CloudFormation quay về trạng thái cũ |
| `HelloWorldFunction may not have authorization defined, Is this okay?` | `y`: API không có xác thực, chấp nhận cho bài lab |
| Save arguments to configuration file | `Y`: lần sau chỉ cần `sam deploy` |

**Đi sâu hơn: `samconfig.toml`**

```toml
version = 0.1
[default.global.parameters]
stack_name = "url-shorten-app"

[default.deploy.parameters]
capabilities = "CAPABILITY_IAM"   # cho phép stack tạo IAM role
confirm_changeset = true
resolve_s3 = true                 # tự tạo/dùng bucket S3 của SAM
region = "ap-southeast-1"
disable_rollback = true           # ⚠️ repo đang bật: deploy lỗi sẽ KHÔNG rollback
```

- Cấu trúc là `[môi-trường.lệnh.parameters]`. Thêm `[prod.deploy.parameters]` rồi chạy `sam deploy --config-env prod` để deploy môi trường khác, với stack name khác.
- Tham số trên dòng lệnh **thắng** giá trị trong file.
- `disable_rollback = true` giúp giữ lại tài nguyên lỗi để điều tra. Nhưng stack sẽ kẹt ở `UPDATE_FAILED`, và bạn phải sửa rồi deploy lại (hoặc rollback tay). Người mới nên để `false`.
- `CAPABILITY_IAM` đủ khi role không đặt tên cố định. Nếu bạn đặt `RoleName:` thì cần `CAPABILITY_NAMED_IAM`.

**Đi sâu hơn: Lambda chạy thế nào**

- **Cold start:** request đầu tiên (hoặc sau một thời gian không dùng) phải tạo môi trường chạy mới: tải code, khởi động runtime, chạy code ngoài handler (`import boto3`…). Thời gian này gọi là pha **INIT**, thường vài trăm ms với Python. Các request sau dùng lại môi trường đó (**warm**) nên nhanh.
  - Mẹo: tạo client `boto3` **ngoài** handler để dùng lại giữa các lần gọi.
  - Từ 1/8/2025, AWS **tính tiền cả pha INIT** cho mọi loại hàm (trước đây hàm zip + managed runtime được miễn).
  - Giảm cold start: *Provisioned Concurrency* (tốn tiền giữ ấm) hoặc *SnapStart* (có cho Java, Python, .NET).
- **Memory: 128 MB – 10.240 MB.** CPU được cấp *tỉ lệ thuận* với memory. Tăng memory đôi khi làm hàm chạy nhanh hơn và rẻ hơn.
- **Timeout:** tối đa **900 giây** (15 phút). Nhưng API Gateway REST mặc định chỉ đợi **29 giây**, nên hàm sau API phải trả lời nhanh.
- **Giá:**
  - 0,20 USD / 1 triệu request.
  - 0,0000166667 USD / **GB-giây** (x86).
  - Free Tier hằng tháng: **1 triệu request + 400.000 GB-giây**.
  - Ví dụ: 1 triệu request × 100 ms × 128 MB = 1.000.000 × 0,1 s × 0,125 GB = 12.500 GB-giây, vẫn nằm trong free.

**Lỗi hay gặp & cách sửa**

- `Error: PythonPipBuilder:Validation - Binary validation failed for python, searched for python in following locations: [...] which did not satisfy constraints for runtime: python3.11` → máy Fedora của bạn có Python 3.13/3.14 chứ không có 3.11. Cách sửa: `sudo dnf install python3.11`, hoặc `sam build --use-container` (build trong Docker image giống Lambda), hoặc đổi `Runtime` sang phiên bản bạn có và Lambda hỗ trợ (ví dụ `python3.13`).
- `Error: Failed to create changeset for the stack: ... Requires capabilities : [CAPABILITY_IAM]` → thiếu `--capabilities CAPABILITY_IAM`.
- Gọi URL bị `{"message":"Missing Authentication Token"}` → sai đường dẫn hoặc sai stage. Lab dùng stage `dev`, URL đúng là `.../dev/hello`, không phải `.../Prod/hello` như mẫu mặc định.
- `Stack ... is in ROLLBACK_COMPLETE state and can not be updated` → lần deploy **đầu tiên** đã lỗi. Xoá stack (`sam delete`) rồi deploy lại.

💰 **Chi phí:** Lambda + API Gateway cho bài lab gần như 0 USD. Bucket S3 của SAM (`aws-sam-cli-managed-default-samclisourcebucket-...`) chứa các bản zip, mỗi bản vài KB đến vài MB.

**Bài tập**

🟢 *Cơ bản*: Làm lại lab. Sửa message thành `"xin chao <tên bạn>"`, chạy `sam build && sam deploy` (không cần `--guided` nữa), rồi gọi lại API.

🟡 *Thực hành*: Thêm biến môi trường `GREETING` vào hàm (qua `Environment: Variables:`), và đọc bằng `os.environ["GREETING"]`. Thêm `Parameters: Stage` (dev/prod) và tạo môi trường `prod` trong `samconfig.toml` với stack name khác. Deploy cả hai.

```yaml
    Type: String
```

</details>

## SAM Local Testing {006}

**Khái niệm cốt lõi**

`sam local` chạy Lambda **trên máy bạn**, bên trong container Docker dùng image giống môi trường Lambda thật. Nhờ vậy bạn sửa và test nhanh, không phải deploy mỗi lần sửa một dòng.

```
sam local invoke  HelloWorldFunction -e events/event.json   # gọi 1 lần với event mẫu
sam local start-api                                          # API giả: http://127.0.0.1:3000
sam local start-lambda                                       # endpoint giả cho AWS CLI/SDK gọi Lambda
sam local generate-event apigateway aws-proxy > ev.json      # sinh event mẫu cho nhiều dịch vụ
```

```bash
cd serverless-application-model/url-shorten-app
sam build
sam local invoke HelloWorldFunction -e events/event.json
sam local start-api
# Terminal khác:
curl http://127.0.0.1:3000/hello
curl -X POST http://127.0.0.1:3000/api/generate-short-url -d '{"url":"https://example.com"}'
```

**File `events/event.json`** trong repo là một event API Gateway mẫu: có `httpMethod`, `path`, `headers`, `body` (chuỗi JSON, chưa parse), `pathParameters`… Đây chính là thứ hàm của bạn nhận trong biến `event`.

**Đi sâu hơn**

- **Cần Docker (hoặc runtime tương thích Docker).** Docker chỉ cần cho `sam local` và `sam build --use-container`; `sam deploy` thì không cần. Trên Fedora, cài Docker Engine (`sudo dnf install docker-ce ...` theo docs.docker.com), thêm user vào group `docker`, rồi đăng xuất và đăng nhập lại. Podman *có thể* chạy được nếu bật socket tương thích Docker (`systemctl --user enable --now podman.socket` và `export DOCKER_HOST=unix:///run/user/$UID/podman/podman.sock`), nhưng đây không phải cấu hình AWS hỗ trợ chính thức.
- **Lambda local vẫn gọi AWS thật.** Khi hàm chạy `boto3.resource('dynamodb')` trên máy, nó dùng credentials AWS CLI của bạn và ghi vào **bảng DynamoDB thật** (nếu đã deploy). Muốn cô lập hoàn toàn thì chạy *DynamoDB Local* (container `amazon/dynamodb-local`) và truyền endpoint qua biến môi trường.
- **`--env-vars env.json`** để ghi đè biến môi trường khi chạy local.
- **`warm_containers = "EAGER"`** (đã có trong `samconfig.toml`): giữ container chạy sẵn, nên các lần gọi sau nhanh hơn.
- **`sam sync --watch`**: tự đẩy code lên AWS mỗi khi bạn lưu file, nhanh hơn deploy đầy đủ. Chỉ dùng cho **môi trường dev**, vì nó bỏ qua changeset.
- **Unit test không cần Docker:** `tests/unit/test_handler.py` import thẳng `hello_world.app` và gọi `lambda_handler(event, None)` bằng pytest. Đây là tầng test nhanh nhất; `sam local` là tầng tích hợp.

```bash
pip install -r tests/requirements.txt --user
python -m pytest tests/unit -v
```

**Lỗi hay gặp & cách sửa**

- `Error: Running AWS SAM projects locally requires a container runtime. Do you have Docker installed and running?` → Docker chưa chạy (`sudo systemctl start docker`), hoặc user chưa thuộc group `docker`.
- `permission denied while trying to connect to the Docker daemon socket` → chưa đăng xuất và đăng nhập lại sau `usermod -aG docker $USER`.
- Gọi local được nhưng lỗi `ResourceNotFoundException: Requested resource not found` → bảng `UrlShortenTable` chưa tồn tại trên AWS (chưa deploy), hoặc credentials đang trỏ **region khác**. Đặt `AWS_DEFAULT_REGION=ap-southeast-1`.

**Khái niệm cốt lõi**

App gồm 2 API:

| API | Lambda | Việc làm |
|---|---|---|
| `POST /api/generate-short-url` body `{"url": "..."}` | `GenerateShortUrlFunction` | Sinh mã 15 ký tự ngẫu nhiên, lưu `{short_url, original_url}` vào DynamoDB |


**Đọc template của lab** (`url-shorten-app/template.yaml`):

```yaml
  MyApi:
    Type: AWS::Serverless::Api        # REST API, stage "dev"
    Properties:
      StageName: dev

  GetUrlFunction:
    Type: AWS::Serverless::Function
    Properties:
      CodeUri: get_url/
      Handler: app.lambda_handler
      Runtime: python3.11
      Role: !GetAtt LambdaExecutionRole.Arn   # role tự viết, dùng chung cho 2 hàm
      Events:
        HelloWorld:                           # (tên event copy từ mẫu, nên đổi thành GetUrl)
          Type: Api
          Properties:
            Path: /link/{short_url}           # {short_url} → event["pathParameters"]["short_url"]
            Method: get
            RestApiId: !Ref MyApi

  UrlShortenTable:
    Type: AWS::DynamoDB::Table
    Properties:
      TableName: UrlShortenTable
      KeySchema: [{ AttributeName: short_url, KeyType: HASH }]   # partition key
      AttributeDefinitions: [{ AttributeName: short_url, AttributeType: S }]
      BillingMode: PAY_PER_REQUEST                               # on-demand
```

**Đi sâu hơn: DynamoDB**

- **Partition key (HASH):** khoá chính dùng để *tìm thẳng* một item, giống tra từ điển theo từ. DynamoDB băm giá trị này để quyết định dữ liệu nằm ở phân vùng nào. Mã ngẫu nhiên 15 ký tự là partition key **rất tốt**, vì giá trị phân tán đều và không bị dồn vào một phân vùng "nóng".
- **Sort key (RANGE, tuỳ chọn):** cho phép nhiều item cùng partition key, được sắp xếp. Ví dụ `user_id` + `created_at`.
- **`get_item`** (theo khoá) rất nhanh và rẻ. **`scan`** đọc *toàn bộ bảng*: chậm và tốn tiền, tránh dùng trong code thật.
- **On-demand (`PAY_PER_REQUEST`):** không phải đoán trước tải, trả theo request. Khoảng 0,625 USD/triệu write và 0,125 USD/triệu read (giá us-east-1, Singapore cao hơn một chút). Hợp với app học và app tải không đều.
- **Provisioned:** đặt trước RCU/WCU. Free Tier 25 RCU + 25 WCU thuộc loại này. Rẻ hơn khi tải đều và lớn.
- Lưu trữ: 25 GB đầu miễn phí (table class Standard).

**Đi sâu hơn: REST API hay HTTP API?**

| | REST API (`AWS::Serverless::Api`) — lab dùng | HTTP API (`AWS::Serverless::HttpApi`) |
|---|---|---|
| Giá | khoảng 3,50 USD / triệu request | khoảng 1,00 USD / triệu request |
| Độ trễ | Cao hơn | Thấp hơn |
| Tính năng | API key + usage plan, request validation, cache, WAF, private endpoint | JWT authorizer (Cognito/Auth0) có sẵn, CORS đơn giản |
| Khi nào chọn | Cần các tính năng quản lý API | Phần lớn API backend đơn giản |

Free Tier của API Gateway: 1 triệu call/tháng trong 12 tháng đầu (với tài khoản theo mô hình cũ; tài khoản tạo từ 15/7/2025 dùng credit Free Tier).

**Đi sâu hơn: IAM, làm đúng cách hơn lab**

Lab tạo policy `dynamodb:*` trên `Resource: "*"`, tức là Lambda được phép **xoá mọi bảng** trong tài khoản. SAM có sẵn **policy templates** giới hạn đúng bảng cần dùng:

```yaml
  GenerateShortUrlFunction:
    Type: AWS::Serverless::Function
    Properties:
      # bỏ "Role:", để SAM tự tạo role với quyền tối thiểu
      Policies:
        - DynamoDBWritePolicy:
            TableName: !Ref UrlShortenTable
      Environment:
        Variables:
          TABLE_NAME: !Ref UrlShortenTable     # đừng hard-code 'UrlShortenTable' trong Python
  GetUrlFunction:
    Properties:
      Policies:
        - DynamoDBReadPolicy:
            TableName: !Ref UrlShortenTable
```

Với hàm, đổi `dynamodb.Table('UrlShortenTable')` thành `dynamodb.Table(os.environ['TABLE_NAME'])`. Bỏ luôn `TableName:` cố định trong bảng để CloudFormation tự đặt tên duy nhất, nhờ vậy deploy được nhiều stack (dev/prod) trong cùng tài khoản.

**Lỗi hay gặp & cách sửa**

- `{"message": "Internal server error"}` (502) → Lambda ném exception hoặc trả sai format (thiếu `statusCode`, `body` không phải chuỗi). Xem log bằng `sam logs -n GetUrlFunction --stack-name url-shorten-app --tail`.
- `KeyError: 'url'` hoặc `JSONDecodeError` → body gửi lên không phải JSON hoặc thiếu trường `url`. Nên kiểm tra đầu vào và trả 400 thay vì để hàm sập.
- `UrlShortenTable already exists` khi deploy stack thứ hai → `TableName` cố định. Bỏ `TableName` như hướng dẫn ở trên.
- `AccessDeniedException ... dynamodb:PutItem` → role không có quyền ghi (ví dụ bạn chỉ gắn `DynamoDBReadPolicy` cho hàm generate).
- Lỗi CORS khi gọi từ trang web khác domain → header CORS chỉ có trong response 200. Còn request **OPTIONS** (preflight) cần cấu hình `Cors:` trên `AWS::Serverless::Api`.

💰 **Chi phí:** vài trăm request khi học gần như 0 USD. `Tracing: Active` bật X-Ray (100.000 trace/tháng miễn phí). Log group CloudWatch mặc định **giữ log mãi mãi**. Hãy đặt retention, ví dụ thêm `AWS::Logs::LogGroup` với `RetentionInDays: 7` cho từng hàm, hoặc chỉnh trên console.

<details><summary>1. Vì sao <code>get_url</code> trả mã 308 chứ không trả 200 kèm URL gốc?</summary>

308 (Permanent Redirect) kèm header `Location` khiến trình duyệt **tự chuyển** sang URL gốc, đúng hành vi của một dịch vụ rút gọn link. Trả 200 thì trình duyệt chỉ hiện ra một đoạn JSON. 301/308 là chuyển hướng vĩnh viễn (trình duyệt có thể cache); 302/307 là tạm thời, hợp hơn nếu bạn muốn đếm lượt click mỗi lần.
</details>

<details><summary>2. Khi nào dùng <code>get_item</code>, khi nào dùng <code>query</code>, vì sao tránh <code>scan</code>?</summary>

`get_item`: lấy đúng 1 item theo khoá chính đầy đủ. `query`: lấy nhiều item cùng partition key (có thể lọc theo sort key). `scan`: đọc mọi item trong bảng, và bạn trả tiền theo dung lượng đã đọc, nên bảng lớn thì vừa chậm vừa tốn. App rút gọn link chỉ cần `get_item`.
</details>

## Nâng cấp tính năng, tổng kết và xoá resources {009-010}

**Khái niệm cốt lõi**

Khi app đã chạy, mỗi lần nâng cấp gồm: sửa code/template → `sam build` → `sam deploy` (xem changeset) → kiểm tra. CloudFormation chỉ cập nhật những tài nguyên thay đổi.

```bash
sam build
sam deploy                         # đọc samconfig.toml; confirm_changeset = true → xem trước
# Changeset hiển thị: + Add / * Modify / - Delete và cột "Replacement" (True = xoá tạo lại!)
sam logs --stack-name url-shorten-app --tail
```

⚠️ Đọc kỹ cột **Replacement**. Ví dụ đổi `KeySchema` hay `TableName` của bảng DynamoDB sẽ khiến CloudFormation **tạo bảng mới và xoá bảng cũ, mất sạch dữ liệu**. Với tài nguyên chứa dữ liệu, đặt thêm:

```yaml
  UrlShortenTable:
    Type: AWS::DynamoDB::Table
    DeletionPolicy: Retain           # xoá stack vẫn giữ bảng
    UpdateReplacePolicy: Retain
```

**Đi sâu hơn: deploy an toàn cho Lambda (canary)**

Repo có file `serverless-application-model/codedeploy_draft.yaml` gợi ý hai thuộc tính:

```yaml
  GetUrlFunction:
    Type: AWS::Serverless::Function
    Properties:
      AutoPublishAlias: live                  # mỗi lần deploy tạo Version mới, alias "live" trỏ tới nó
      DeploymentPreference:
        Type: Canary10Percent10Minutes        # 10% traffic sang version mới, 10 phút sau chuyển hết
        Alarms:
          - !Ref GetUrlErrorsAlarm            # alarm kêu → CodeDeploy tự quay về version cũ
```

- SAM tự tạo **CodeDeploy application + deployment group** cho Lambda. Cơ chế giống canary của ECS ở chương 11, nhưng thay vì target group thì nó chuyển **trọng số giữa hai version của alias**.
- Các kiểu có sẵn: `Canary10Percent5Minutes`, `Canary10Percent10Minutes`, `Linear10PercentEvery1Minute`, `AllAtOnce`…
- Có thể thêm hook `PreTraffic` / `PostTraffic` (một Lambda test) trước và sau khi chuyển traffic.
- API Gateway phải gọi **alias** (SAM tự nối khi bạn dùng `AutoPublishAlias`).

**Tổng kết chương**

```
template.yaml (SAM) ──sam build──▶ .aws-sam/ ──sam deploy──▶ CloudFormation stack
                                                     ├─ Lambda × 3 (+ version/alias)
                                                     ├─ API Gateway REST (stage dev)
                                                     ├─ DynamoDB (on-demand)
                                                     ├─ IAM role/policy
                                                     └─ CloudWatch log group (tự tạo khi hàm chạy lần đầu)
```

**Dọn dẹp (video 010)**

**Lỗi hay gặp & cách sửa**

- `sam delete` báo `DELETE_FAILED` vì bucket S3 không rỗng (nếu template có tạo bucket) → `aws s3 rm s3://<bucket> --recursive`, rồi xoá lại.
- Deploy với `DeploymentPreference` báo lỗi quyền CodeDeploy → SAM cần tạo role cho CodeDeploy. Kiểm tra `capabilities` có `CAPABILITY_IAM`.
- Changeset báo `No changes to deploy` → bạn quên `sam build`, nên `.aws-sam/build` vẫn là code cũ.
- Stack kẹt `UPDATE_FAILED` (vì `disable_rollback = true`) → sửa lỗi rồi deploy lại, hoặc chạy `aws cloudformation rollback-stack --stack-name url-shorten-app`.
